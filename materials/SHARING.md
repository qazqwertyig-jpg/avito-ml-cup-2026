# Работа с проектом в команде

В репозитории сохранены исходники официальных бейзлайнов и наших экспериментов,
тесты, журнал решений, JSON-отчёты, логи запусков и компактные обученные модели
(`model.txt`, `.pt`, `.joblib`). Результаты неудачных попыток также сохранены.

## С чего начать

1. Прочитать [описание задачи](HACKATHON.md).
2. Посмотреть [журнал экспериментов](EXPERIMENTS.md): там находятся метрики,
   сравнения, выводы и команды воспроизведения.
3. Открыть [каталог сохранённых запусков](../experiments/README.md), чтобы найти
   отчёты конкретного эксперимента.
4. Прочитать [контекст продолжения работы](HANDOFF.md). Это снимок рабочего
   контекста; хронология фактических запусков находится в журнале и отчётах.
5. Посмотреть [результат проверки перед публикацией](PUBLISH_CHECK.md), включая
   известное падение одного теста в существующей локальной среде.

## Данные и крупные артефакты

Исходный датасет соревнования, вычисленные массивы `.npz`/`.npy`, прогнозы и
сабмиты `.parquet` не включены в Git. Только массивы экспериментов занимают
около 44 ГиБ, а прогнозы — около 2 ГиБ. Они остаются на исходной рабочей машине.
Ссылки на такие файлы в историческом журнале обозначают локальные пути:
на GitHub они не откроются. JSON с метриками и проверками доступен в репозитории.

Скачайте `competition.zip` (19,2 ГБ) из раздела [«Данные для участников» на ODS](https://ods.ai/competitions/avitotechrecsys2026/dataset).
Распакуйте архив в корень клона. Проверьте, что `train/`, `val/`, `test/`
и `sample_submission.parquet` лежат непосредственно в `competition/`, без
дополнительного уровня вложенности. Каждый сплит содержит `impressions/`
и `item_embeddings/`. Формат описан в [README данных](../competition/readme.md).

Файл [LOCAL_ARTIFACTS.csv](LOCAL_ARTIFACTS.csv) перечисляет исключённые массивы,
прогнозы и шаблоны сабмитов с относительными путями и размерами на момент
подготовки репозитория. Это инвентаризация, а не резервная копия.
Для повторения расчётов используйте команды соответствующего цикла в журнале.
Для точного повторного использования сохранённых прогнозов их нужно отдельно
получить у владельца исходной рабочей машины по путям из инвентаризации.

## Запуск

Рабочая среда экспериментов: Python 3.11, `uv`, PowerShell. Базовый набор:

```powershell
$rankingPackages = @('--no-project', '--python', '3.11', '--with', 'numpy==1.26.4', '--with', 'polars==1.14.0', '--with', 'pyarrow==19.0.1', '--with', 'lightgbm==4.6.0')
uv run @rankingPackages --with torch==2.10.0 python -m unittest discover -s experiments
```

Зависимости официальных бейзлайнов закреплены в `baseline/pyproject.toml`
и `baseline/uv.lock`. Некоторые нейросетевые эксперименты использовали отдельную
среду DirectML; точные команды и версии для конкретного запуска ищите в журнале.
Запускайте команды из корня проекта и задавайте новые выходные каталоги, чтобы
сохранять предыдущие результаты.

## Новые эксперименты

Сохраняйте код в `experiments/`, отчёты и небольшие модели — в отдельном каталоге
запуска. В `materials/EXPERIMENTS.md` записывайте гипотезу, параметры, seed,
объём данных, метрики, вывод и команду воспроизведения. Большие массивы и
предсказания автоматически исключены через `.gitignore`.

После проверки нового запуска добавляйте код, отчёты и журнал в коммит и
отправляйте изменения в GitHub. Эта первоначальная публикация сама по себе
не настраивает автоматическую синхронизацию последующих экспериментов.

Приватный репозиторий видят только владелец и приглашённые участники.
Доступ выдаётся в GitHub: Settings → Collaborators.
